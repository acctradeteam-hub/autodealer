# Agent Platform — стартовый набор

Каркас платформы AI-агентов компании. Запускается одной командой, работает на тестовых данных
студии внедрения AI-агентов «Нейрокрафт» (~90 человек). Дальше вы добавляете свои знания, роли и агентов.

```bash
cp .env.example .env    # необязательно: без ANTHROPIC_API_KEY работает демо-режим
docker compose up --build
```

Откройте http://localhost:8000 и переключайте «Смотреть как» в шапке: интерфейс меняется по роли сотрудника.
`make test` прогоняет проверки границ и примеры агентов.

## Идея: 3 сущности, 1 правило

| Сущность | Где лежит | Что это |
|---|---|---|
| **Контекст** | `knowledge/<раздел>/*.md` | Знания компании. Одна запись = один файл; поле `access` — каким ролям она видна |
| **Роль** | `config/roles.yaml`, `config/people.yaml` | Кто что видит (через `access` записей) и каких агентов запускает (через `roles` агента) |
| **Агент** | `agents/<имя>/` | Независимая программа на любом языке с контрактом «вход → выход» (JSON Schema) |

**Правило: платформа держит границы, агент держит логику.** Знания и модели агент получает только
через платформу, по токену запуска. Токен привязан к роли того, кто запустил агента, и живёт 15 минут.

```
сотрудник ──POST /api/agents/<имя>/run──► платформа: роль? вход по схеме? ──нет──► отказ, агент не вызывается
                                               │ да
                                               ▼
                               агент POST /run {input, run_token, platform_url}
                                 ├─ GET  /api/context/...   записи, видимые роли, только из объявленных разделов
                                 └─ POST /api/llm/messages  модель через LLM Gateway (ключ только у платформы)
                                               │ {output, steps}
                                               ▼
                               платформа: выход по схеме? → журнал и трассировка
```

`platform/` — ядро: Context API, Run API, LLM Gateway (считает токены и стоимость), журнал, интерфейс,
Python SDK одним файлом (`platform/sdk/agent_sdk.py`).

## Как добавить знание — 1 шаг

Положите файл в `knowledge/<раздел>/` и нажмите «Синхронизировать» на главной
(или перезапустите платформу):

```markdown
---
section: pricing
access: [ceo, finance]      # кто видит запись
owner: elena                # кто отвечает за актуальность
updated: 2026-11-01
kind: cost                  # любые свои поля: по ним фильтрует ctx.get("pricing", kind="cost")
---
# Себестоимость — AI-аудит
...
```

Доступ задаётся только на уровне записи. Чувствительное (как себестоимость) — отдельная запись
с другим `access`, а не абзац внутри общей.

## Как добавить сотрудника — 1 шаг

Допишите его в `config/people.yaml`, указав `id`, `name`, `position`, `role` и `token`, затем нажмите «Синхронизировать».
Новая роль — строка в `config/roles.yaml` плюс эта роль в `access` нужных записей.

## Как сделать агента

1. `cp -r agents/_template agents/my-agent`
2. В `agents/my-agent/agent.yaml` задайте `name: my-agent`, вход и выход (JSON Schema), нужные разделы
   `context` и роли `roles`. В `Dockerfile` замените `my-agent` на имя папки.
3. Напишите логику в `main.py`:
   ```python
   from agent_sdk import agent, llm

   @agent
   def run(input, ctx):
       clients = ctx.get("clients", name=input["client"])   # только видимое роли
       cases = ctx.search("логистика", section="cases")     # полнотекстовый поиск
       ctx.step("Свой шаг", found=len(cases))                # попадёт в трассировку
       return {"brief": llm("Кратко: " + clients[0]["body"], mock="демо-ответ")}
   ```
4. Добавьте сервис в `docker-compose.yml` (имя сервиса = имя агента; платформа зовёт `http://<имя>:8080`):
   ```yaml
   my-agent:
     build: {context: ., dockerfile: agents/my-agent/Dockerfile}
   ```
5. Опишите 3–5 примеров в `agents/my-agent/tests/cases.yaml`.
6. `docker compose up --build -d my-agent`, нажмите «Синхронизировать», запустите агента из интерфейса. Потом `make test`.

Агент на другом языке — любой HTTP-сервис с `POST /run`, который принимает `{input, run_token, platform_url}`
и возвращает `{output, steps}`. За знаниями и моделью он ходит в API ниже с заголовком `Authorization: Bearer <run_token>`.

## API

| Кто | Запрос | Что делает |
|---|---|---|
| сотрудник | `POST /api/agents/<имя>/run` `{"input": {...}}` | Запуск. 403 — роль не может запускать агента; 422 — вход не по схеме |
| сотрудник | `GET /api/runs`, `GET /api/runs/<id>` | Журнал и трассировка (руководитель видит все запуски) |
| сотрудник | `PATCH /api/runs/<id>` `{"edited_output", "review_status"}` | Правка результата и статус: `draft` / `approved` / `sent` |
| агент | `GET /api/context/records/<раздел>?поле=значение` | Записи раздела |
| агент | `GET /api/context/search?q=...&section=...` | Поиск по разделам агента |
| агент | `POST /api/llm/messages` `{"messages"\|..., "model"?, "mock_response"?}` | Модель: `claude-opus-5-5` (по умолчанию), `claude-sonnet-5-5`, `claude-haiku-5-5` |

Сотрудник передаёт `Authorization: Bearer <token из people.yaml>`. Например, из любой программы:
`curl -X POST localhost:8000/api/agents/client-brief/run -H 'Authorization: Bearer demo-ivan' -H 'Content-Type: application/json' -d '{"input":{"client":"ТрансЛогистик"}}'`

## Что в наборе

- **client-brief** (17 строк): справка по клиенту из контекста. Показывает, как мало нужно для агента.
- **commercial-proposal**: LLM подбирает услуги, затем код считает стоимость и сроки по прайсу (`pricing.py`, без LLM),
  поиск находит похожие кейсы, а LLM пишет КП по шаблону. Код проверяет, что итоговая сумма не изменилась.
  Запускают роли sales и ceo.
- **Проверки (`make test`)**: себестоимость не попадает к продажам ни в выход, ни в трассировку, а трассировка
  показывает, сколько записей скрыто ролью. Запуск от delivery получает отказ ещё до вызова агента. Запрос
  к необъявленному разделу получает отказ. На выход не по схеме приходит понятная ошибка. Проходят все
  `agents/*/tests`. Без Docker: `TEST_DATABASE_URL=postgresql://... make test-local`.
- **Демо-режим**: без ключа Gateway возвращает `mock` из запроса агента, а стоимость считается по оценке
  токенов. С ключом в `.env` работают настоящие модели, и сумма в КП проверяется кодом.

## Что дальше

- **Семантический поиск**: колонка `embedding` и pgvector рядом с полнотекстовым `tsv` в таблице `knowledge`.
- **Агенты как MCP-инструменты**: тонкий MCP-сервер поверх Run API, чтобы агентов можно было вызывать из Claude и IDE
  с токеном сотрудника.
- **Вызов агентов агентами**: агент запускает другого агента через Run API с тем же токеном запуска, роль
  наследуется, а трассировка становится деревом.
- **Файлы на входе и выходе**: хранилище объектов и поле `format: file` в схеме, ссылки на файлы выдаются по токену.
- **Асинхронные запуски**: очередь (`status: queued`), вебхук или SSE по завершении. Сейчас запуск синхронный.
- **Ограничение сети агентов**: внутренняя сеть compose без выхода наружу (`internal: true`), чтобы агент
  мог дойти только до платформы.
- **Вход сотрудников через SSO** вместо демо-токенов из `people.yaml`.
