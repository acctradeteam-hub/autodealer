# Аналитик лотов

Разбирает **сохранённые HTML-страницы аукционных лотов** в структурированную
таблицу: марка, модель, год, пробег, VIN, дефекты, история и остальные поля,
нужные для решения о максимальной ставке.

Работает офлайн, по файлам. В сеть не выходит и никуда ничего не отправляет.

## Что уже проверено, а что нет

| | Состояние |
|---|---|
| Разбор HTML одного лота → TSV + XLSX + накопительная таблица | **работает**, проверено тестами |
| Разметка Copart / IAAI (подписи полей, таблицы) | **работает** на синтетических страницах в `tests/fixtures/` |
| Разметка Manheim / ACV / OPENLANE / CarMax (данные в JSON внутри страницы) | **работает** на синтетической странице; реальные страницы не проверялись |
| **ACV**: карточка лота из сохранённой страницы Marketplace | **работает на реальной странице** (сентябрь 2026): объявления инспектора, отметки Carfax, коды OBD, протектор, котировка доставки |
| **Manheim**: встроенный JSON объявления (MMR, ритейл, AutoCheck, CR, шины, ключи) | **работает на реальной странице** (сентябрь 2026) |
| **ADESA**: карточка лота без карусели «Similar Vehicles» (опт, ритейл, grade, повреждения, AutoCheck) | **работает на реальной странице** (сентябрь 2026) |
| **CarMax Auctions**: открытая карточка поверх результатов поиска (объявления, повреждения, протектор, дорожка/номер) | **работает на реальной странице** (сентябрь 2026) |
| **CarMax: watch list целиком** — строка на каждую машину, KBB / MMR / история из ваших заметок | **работает на реальной странице** (28 машин, 29.09.2026) |
| **Списки ADESA, ACV, Manheim** (поиск, сохранённый поиск) — строка на каждую машину | **работает на реальных страницах** (25 / 12 / 20 машин, 29.09.2026). Manheim — из JSON каждой карточки: MMR, AutoCheck, анкета продавца, Buy Now. ADESA — VIN собирается из двух половинок. Вердикт по списку — предварительный: истории и повреждений из карточки лота в нём нет |
| Расчёт потолка ставки (сборы, ремонт, детейлинг, смог, история, прибыль) | **работает**, проверено тестами. Настоящие сетки сборов: ACV (с 01.05.2026), CarMax (Tier 3 — CA, январь 2026), IAA, Copart. Manheim и ADESA — **примерные**, сверены с реальными покупками |
| Автоматическое чтение KBB / MMR / CarGurus | **не сделано**, см. «Этап 2» ниже |
| Распознавание дефектов по фотографиям | **не сделано**: собираются только ссылки на фото |

Дефекты берутся из текста страницы (поля повреждений, объявления продавца,
описание), а не из фотографий.

## Установка

```bash
python3 -m pip install -r requirements.txt
```

Нужен Python 3.10 или новее. `pandas` не требуется.

## Запуск

```bash
# разобрать все страницы в папке
python3 -m lot_analyzer samples/

# один файл, с явным указанием аукциона (если он не определился сам)
python3 -m lot_analyzer samples/lot_58392011.html --auction Copart

# только текущий прогон, без обновления накопительной таблицы
python3 -m lot_analyzer samples/ --no-cumulative
```

Как сохранять страницы лотов — в [`samples/README.md`](samples/README.md).

### Что появится после запуска

| Файл | Что в нём |
|---|---|
| `out/lots_ГГГГ-ММ-ДД.tsv` | результат текущего прогона |
| `out/lots_ГГГГ-ММ-ДД.xlsx` | то же в Excel: закреплённая шапка, автофильтр, лист «Памятка» |
| `out/lots_cumulative.tsv` | **накопительная таблица** по всем прогонам |
| `out/lots_cumulative.xlsx` | накопительная таблица в Excel |
| `valuations/manual_values.tsv` | шаблон ручных оценок: по строке на каждый новый VIN |

Дубликаты в накопительной таблице отсекаются по VIN, а при его отсутствии — по
паре «аукцион + номер лота». Повторный разбор той же страницы обновляет строку
и **не затирает** колонки, заполненные вручную.

## Колонки таблицы

Заполняются автоматически со страницы лота:

`Аукцион`, `Лот`, `VIN`, `VIN корректен`, `Год`, `Марка`, `Модель`,
`Комплектация`, `Пробег, мили`, `Достоверность пробега`, `Тип титула`,
`Штат титула`, `Первичное повреждение`, `Вторичное повреждение`,
`Дефекты (сводно)`, `Ключи`, `На ходу`, `Локация`, `Дата продажи`,
`Текущая ставка, $`, `Оценка ACV, $`, `Описание лота`,
`История (со страницы)`, `Кол-во фото`, `Ссылки на фото`, `Ссылка на лот`,
`Файл-источник`, `Дата разбора`, `Проверить`.

Заполняются вручную (в XLSX подсвечены жёлтым), значения берутся из
`valuations/manual_values.tsv`:

`KBB Private Party, $`, `Adjusted MMR, $`, `Ритейл CarGurus, $`,
`Рейтинг CarGurus`, `Максимальная ставка, $`, `Carfax / AutoCheck`,
`Condition Report`.

`Adjusted MMR` и `Condition Report` заполняются автоматически, **если** они есть
в самой сохранённой странице (так бывает у Manheim и ACV).

### Колонка «Проверить»

Ключевая колонка для контроля. Парсер пишет в неё:

- какие важные поля не нашлись;
- что контрольная цифра VIN не сходится (опечатка или битый VIN);
- что год на странице расходится с годом, закодированным в VIN;
- что значение взято из текста страницы, а не из поля, — то есть менее надёжно;
- что пробег переведён из километров или выглядит неправдоподобно.

Пустая клетка = все критичные поля найдены. Строки с замечаниями в XLSX
подсвечены. **Ручная проверка перед ставкой обязательна:** парсер читает
разметку, он не понимает смысла лота.

## Как устроено

Разметку аукционов мы не контролируем, и она меняется. Поэтому вместо жёстких
CSS-селекторов каждая страница разбирается четырьмя независимыми способами, а
поля затем ищутся по словарю синонимов подписей:

1. **JSON-LD** — блок `<script type="application/ld+json">` со схемой Vehicle;
2. **JSON внутри страницы** — `__NEXT_DATA__`, `__PRELOADED_STATE__` и подобное;
3. **пары «подпись → значение»** из разметки: `dt/dd`, `th/td`, `data-uname`,
   `aria-label`, классы `label`/`value`, конструкция «Подпись: значение»;
4. **регулярные выражения по видимому тексту** — последний рубеж.

Если аукцион переделает вёрстку, поля обычно продолжат находиться следующим
способом. А если поле всё же потерялось, это видно в колонке «Проверить», а не
превращается в тихо пустую клетку.

| Файл | Назначение |
|---|---|
| `lot_analyzer/schema.py` | колонки таблицы и какие из них ручные |
| `lot_analyzer/normalize.py` | VIN (контрольная цифра, год), деньги, пробег, даты |
| `lot_analyzer/extract.py` | четыре способа снять данные с HTML |
| `lot_analyzer/parsers.py` | определение аукциона, синонимы подписей, сборка строки |
| `lot_analyzer/report.py` | TSV, XLSX, накопительная таблица, ручные оценки |
| `lot_analyzer/pages.py` | чтение `.html` и `.mhtml` |
| `lot_analyzer/acv.py` | карточка лота ACV: только блок лота, без списка и фильтров Marketplace |
| `lot_analyzer/manheim.py` | Manheim: JSON объявления из API Cox Automotive, встроенный в страницу |
| `lot_analyzer/app.py` | «одно окно» (локальный сервер 127.0.0.1): поиск по всем аукционам, файлы из «Загрузок» |
| `config/search_urls.json` | ссылки поиска аукционов для «одного окна» |
| `lot_analyzer/market.py` | результаты торгов → `data/market_history.csv` и доли «цена ÷ KBB / MMR» в настройках |
| `lot_analyzer/lists.py` | списки ADESA и ACV: карточка машины = блок, в котором ровно один пробег |
| `lot_analyzer/sites_text.py` | ADESA и CarMax: чтение карточки по подписям на экране (классы разметки у них случайные) |
| `lot_analyzer/bid.py` | расчёт потолка ставки; запуск для одной машины |
| `config/costs.json` | сборы аукционов, расходы, цель прибыли, скидки за историю |
| `tools/bookmarklet/` | закладка «Сохранить для анализа»: исходник, сборка (`build.py`), страница установки, проверка в Chromium |
| `lot_analyzer/__main__.py` | запуск из командной строки |

### Новый аукцион или изменившаяся вёрстка

Обычно достаточно добавить несколько подписей в `SITE_SYNONYMS` в
`lot_analyzer/parsers.py` — новый парсер писать не нужно.

## «Одно окно»: одна машина — все аукционы

Двойной щелчок по `start_window.bat` (Windows) или `start_window.command` (Mac),
либо `python3 -m lot_analyzer.app` — в браузере откроется http://127.0.0.1:8765.

1. Впишите машину («Honda Civic»), годы, пробег и, если знаете, KBB PP.
2. Кнопки «CarMax ↗ ACV ↗ Manheim ↗ ADESA ↗» открывают поиск на каждом аукционе
   (ADESA — сразу с фильтром; для остальных один раз запомните свой сохранённый
   поиск прямо в окне — дальше кнопка откроет его).
3. На каждой вкладке нажмите закладку «💾 Сохранить для анализа». Окно само
   подхватывает файлы из «Загрузок» и показывает одну таблицу по всем аукционам:
   потолок, «рынок», прибыль, вердикт, ссылка на лот. Сверху — что можно брать.

Окно работает только на вашем компьютере и никуда ничего не отправляет.
Стратегия, на которую настроены правила отбора, — `docs/STRATEGY_turnover.md`.

## Главный сценарий: watch list → таблица с потолками

1. Добавьте машины в watch list аукциона и впишите в заметку к машине то, что
   знаете: `KBB 11,905$` (или `KBB PP $19,940`), `MMR $13,850`, историю из
   Carfax — `3 owners, 1 accident`, свою цену продажи на Facebook — `FB 9500`,
   свой прокси — `MP 5600` (сверяется с потолком). Если значение встречается в
   заметке дважды, берётся последнее.
2. Откройте watch list и нажмите закладку **«💾 Сохранить для анализа»** —
   файл ляжет в «Загрузки» (установка: откройте `tools/bookmarklet/install.html`
   и перетащите кнопку на панель закладок). Можно и по-старому: Ctrl+S →
   «Веб-страница, полностью». Если заодно открыть карточку одной машины, её
   повреждения и протектор тоже попадут в таблицу.
3. `python3 -m lot_analyzer samples/` — в `out/` таблица: сверху «МОЖНО до $X»
   по убыванию потолка, внизу «ПРОПУСТИТЬ» с причиной.

Так же разбираются результаты поиска и сохранённые поиски ADESA, ACV и Manheim:
закладку можно нажимать на любой странице со списком машин. Если ни KBB, ни
своей цены нет, цена продажи берётся из ритейл-оценки аукциона × 0.85, а если
есть только опт/MMR — MMR × 1.3 (`mmr_retail_factor`); это грубый ориентир.

## Результаты торгов: сколько на самом деле платят

После торгов сохраняйте результаты — «My List» CarMax (PDF), печатный run list
с заметками и строкой «Sold $…» (PDF), CSV «DETAILED RESULTS - ALL LANES» — и запускайте:

```bash
python3 -m lot_analyzer.market results/*.pdf results/*.csv --update-config
```

Записи копятся в `data/market_history.csv` (строки «My List» без VIN сопоставляются
с результатами по дорожке/номеру, только если совпадают год и марка). Сводка
«цена продажи ÷ KBB PP» и «÷ MMR» — отдельно для чистых машин и с тяжёлыми
дефектами — записывается в раздел `market` файла `config/costs.json`, а в
таблице появляется колонка «Рынок (обычно платят)» и пометка в вердикте:
«рынок ≈ $X — потолок ниже, выиграть вряд ли» или «шанс есть».

По результатам CarMax Murrieta/Oceanside 21.09 и 28.09.2026 (KBB — из заметок
покупателя): чистые машины уходят за медиану **0.78 × KBB PP** (половина — от 0.69
до 0.85), с тяжёлыми дефектами — за 0.64 × KBB PP. Колонки KBB и MMR в таблицах,
где они досчитаны (дробные центы, KBB ≈ MMR), не используются: из таких файлов
берутся только VIN, статус и цена.

## Расчёт максимальной ставки

Для каждой строки таблицы считаются колонки «Вердикт», «Потолок ставки
(расчёт)», «Расходы сверх ставки», «Прибыль при потолке» и «Расчёт по статьям».
Логика — в `lot_analyzer/bid.py`, все цифры — в `config/costs.json`.

```
цена продажи   = «Цена продажи (моя оценка)», иначе KBB Private Party (ZIP 92620) × коэффициент
− скидка за историю (ДТП 5–15%, 4+ владельцев, аренда — по тексту Carfax / CR)
− ремонт («Ремонт (моя оценка)», иначе резерв + надбавки за слова вроде «check engine»)
− детейлинг, смог, доставка, дилер, реклама, содержание, резерв на непредвиденное
− цель прибыли (большее из $ и % от цены продажи)
= предел «всё включено»;  потолок = наибольшая ставка, при которой ставка + сборы аукциона ≤ предела
```

Брендированный титул, проблемы с пробегом, повреждение рамы, подушки,
затопление → «ПРОПУСТИТЬ». Отрицания вида «No accidents reported» распознаются.

Для ACV ремонт считается по находкам инспектора: каждой неисправности
(«Climate Control Not Working», «Punctured Bumper», «Damaged Tires», коды OBD,
протектор ≤ 4/32", один ключ…) соответствует сумма в `recon_keywords`
`config/costs.json`. «Structural Alteration», «Mileage inconsistency» → «ПРОПУСТИТЬ»;
«Recovered Theft» → −10% к цене; «Title Absent» → предупреждение в вердикте.

Если своей цены продажи и KBB нет, берётся розничная оценка самого аукциона
(Manheim Retail, ADESA Retail) × 0.85 — это ориентир дилерской розницы, на
Facebook Marketplace обычно дешевле; коэффициент — `auction_retail_factor`.
Стоп-факторы проверяются до цены: такая машина — «ПРОПУСТИТЬ» при любой цене.

Быстрый расчёт одной машины без HTML-страницы:

```bash
python3 -m lot_analyzer.bid --sale 8500 --auction Manheim --carfax "1 accident, 3 owners" --mmr 5200 --bid 3800
```

Сетки сборов ACV, CarMax (Tier 3 — CA, январь 2026), IAA и Copart — настоящие.
Manheim и ADESA сетку не публикуют: в файле примерные, сверенные с реальными
покупками (Manheim $9,250 → $535, ADESA $4,900 → $350); у ADESA сверяйте со
сбором в карточке лота. Доставка сейчас 0 — забираете сами; при перевозчике — 250.
Цель прибыли $1500, сбор дилера $300 за машину уже вписаны.

## Этап 2: KBB, Adjusted MMR, CarGurus

Задача «программа читает значения с сайтов KBB, Manheim и CarGurus» **в этом
виде не решается** автоматически. Что проверено на 22.09.2026:

1. **Из этой облачной сессии сайты недоступны.** Проверено запросами: к
   `kbb.com`, `cargurus.com`, `manheim.com`, `copart.com`, `iaai.com` сетевой
   шлюз среды отвечает `403` на этапе соединения. Это ограничение среды
   исполнения, а не настройка парсера.
2. **Все три источника закрыты авторизацией и платными условиями.**
   - Manheim: MMR отдаётся официальным Valuations API, доступ выдаёт
     представитель Cox Automotive / Manheim (контакт для запроса —
     `DataSyndication@coxautoinc.com`), портал — `developer.manheim.com`.
   - KBB: значения отдаются через коммерческие продукты B2B (`b2b.kbb.com`,
     `developer.kbb.com`), доступ по договору.
   - CarGurus: Instant Market Value и рейтинги сделки — закрытый партнёрский
     доступ; использование бейджа Great Deal ограничено их условиями.
3. **Разбор страниц этих сайтов «в обход» логина не предлагается:** это
   нарушение условий использования сервисов и ломается при любой правке вёрстки.

### Три рабочих пути, по возрастанию стоимости

| Путь | Что нужно | Что даёт |
|---|---|---|
| **A. Ручной ввод** (работает сейчас) | ничего | Значения вписываются в `valuations/manual_values.tsv`, подставляются по VIN |
| **B. Сохранённые страницы оценок** | сохранять страницу KBB / Manheim / CarGurus так же, как страницу лота | Значения читаются из ваших же сохранённых страниц: логин ваш, обхода защиты нет. Требует настройки на реальном примере каждой страницы |
| **C. Официальный API** | договор и ключи доступа от Cox Automotive (MMR) и KBB; для CarGurus — партнёрский доступ | Полная автоматизация. Нужна среда с доступом в интернет — локальный компьютер или сервер, не эта веб-сессия |

Путь **B** — ближайший осмысленный шаг: он ничего не нарушает и переиспользует
уже готовый разбор HTML. Для настройки нужна одна сохранённая страница каждого
типа (KBB Private Party для конкретного VIN, карточка MMR, страница CarGurus).

## Ограничения, о которых стоит помнить

- **Фотографии не анализируются.** Собираются ссылки и их количество. Дефект,
  видимый только на фото, в таблицу не попадёт.
- **Страницы со списком лотов** (результаты поиска, run list) не разбираются.
- **Carfax / AutoCheck / Condition Report** — отдельные документы; сейчас это
  ручные колонки.
- **Числа со страницы не перепроверяются.** Текущая ставка и оценка ACV берутся
  как есть; это отправная точка для расчёта, а не готовая максимальная цена.
